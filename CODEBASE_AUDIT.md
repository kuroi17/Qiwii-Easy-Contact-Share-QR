## 2. Critical & Platform Deployment Bugs (P1)

### 2.1 Asset Path Casing Mismatch (Runtime Crash on Android / iOS / Linux)
- **Files:** 
  - `contactqr_flutter/lib/features/home/presentation/home_screen.dart` (lines 220, 292)
- **Problem:**
  Code references `Image.asset('assets/Qiwii_logo.png')` with a capital `Q`. The actual file in the assets folder is `assets/qiwii_logo.png` (lowercase `q`).
- **Impact:**
  While Windows is case-insensitive, Linux, Android, and iOS release builds are case-sensitive. This will trigger a fatal runtime exception (`Unable to load asset: assets/Qiwii_logo.png`) on real mobile devices.
- **Recommended Fix:**
  Update all occurrences to `assets/qiwii_logo.png`.

---

### 2.2 Missing iOS Photo Library Permission (`NSPhotoLibraryUsageDescription`)
- **Files:**
  - `contactqr_flutter/ios/Runner/Info.plist`
- **Problem:**
  `ScannerScreen` allows scanning QR codes from images using `ImagePicker().pickImage(source: ImageSource.gallery)`, but `Info.plist` does not declare `NSPhotoLibraryUsageDescription`.
- **Impact:**
  On iOS devices, tapping "Upload from Photos" will cause an immediate app crash or trigger automatic rejection during Apple App Store review.
- **Recommended Fix:**
  Add the permission string to `Info.plist`:
  ```xml
  <key>NSPhotoLibraryUsageDescription</key>
  <string>Qiwii needs photo library access so you can scan QR codes from your images.</string>
  ```

---

### 2.3 Missing iOS Custom URL Schemes (`CFBundleURLTypes`)
- **Files:**
  - `contactqr_flutter/ios/Runner/Info.plist`
- **Problem:**
  The custom schemes `qiwii` and `contactqr` are not registered in `Info.plist`.
- **Impact:**
  On iOS, tapping shared links using `qiwii://t#...` in Safari, Notes, or Messages will fail to open the application.
- **Recommended Fix:**
  Add `CFBundleURLTypes` to `Info.plist`:
  ```xml
  <key>CFBundleURLTypes</key>
  <array>
      <dict>
          <key>CFBundleURLSchemes</key>
          <array>
              <string>qiwii</string>
              <string>contactqr</string>
          </array>
      </dict>
  </array>
  ```

---

### 2.4 Missing Android App Link Intent Filter for `kuroi17.github.io`
- **Files:**
  - `contactqr_flutter/android/app/src/main/AndroidManifest.xml` (lines 51–57)
- **Problem:**
  `AndroidManifest.xml` only declares an intent filter for `host="qiwii.app"`, but the actual deployed web bridge URL generated by `QrCodec` is `https://kuroi17.github.io/Qiwii/#...`.
- **Impact:**
  Clicking the shared link on Android will open Chrome browser rather than directly intercepting and launching the Qiwii native app.
- **Recommended Fix:**
  Add `kuroi17.github.io` to the intent filter:
  ```xml
  <data android:scheme="https" android:host="kuroi17.github.io" android:pathPrefix="/Qiwii" />
  <data android:scheme="https" android:host="kuroi17.github.io" android:pathPrefix="/Qiwii-Easy-Contact-Share-QR" />
  ```

### 2.5 Search Filter "Select All" Overwriting Previously Selected Contacts
- **Files:**
  - `contactqr_flutter/lib/features/contacts/presentation/send_screen.dart` (line 170)
  - `contactqr_flutter/lib/features/import/presentation/received_screen.dart` (line 131)
  - `contactqr_flutter/lib/features/contacts/providers/sender_provider.dart` (line 116)
  - `contactqr_flutter/lib/features/import/providers/receiver_provider.dart` (line 92)
- **Problem:**
  When searching contacts (e.g. query "Juan" with 2 results), tapping **"Select all"** replaces `selectedIds` with only the filtered IDs:
  ```dart
  state = state.copyWith(selectedIds: allFilteredIds);
  ```
- **Impact:**
  If a user had previously selected 5 contacts before searching, those 5 contacts are silently discarded and replaced only with the 2 filtered results.
- **Recommended Fix:**
  Use Set Union (`state.selectedIds.union(filteredIds)`) when selecting from filtered search results, and remove only filtered matches when clearing.

---

### 2.6 Camera QR Infinite Re-Scan Loop on Modal Dismissal
- **Files:**
  - `contactqr_flutter/lib/features/qr/presentation/scanner_screen.dart` (lines 285–295)
- **Problem:**
  When scanning a PIN-protected QR code and `EnterPinModal` is dismissed (user swipes down or cancels), `_resetScanner()` immediately sets `_isProcessing = false`. Because the camera continues pointing at the QR code at 60fps, `_onDetect` fires again within ~16ms.
- **Impact:**
  The user gets caught in an infinite popup loop of the PIN modal until they quickly pull the camera away.
- **Recommended Fix:**
  Add a 2.5-second cooldown timer before re-analyzing the same detected QR barcode.

---

### 2.7 Cold-Boot Deep Link Navigation Trap on "Done" Button
- **Files:**
  - `contactqr_flutter/lib/features/import/presentation/result_screen.dart` (line 127)
- **Problem:**
  At the end of a transfer, the "Done" button executes:
  ```dart
  Navigator.popUntil(context, (route) => route.isFirst);
  ```
- **Impact:**
  When the app is opened directly via a web share link (cold boot), `ScannerScreen` is the root route. Popping until first leaves the user stranded on a blank scanner screen or terminates the app instead of navigating to `HomeScreen`.
- **Recommended Fix:**
  Use `Navigator.pushAndRemoveUntil(context, MaterialPageRoute(builder: (_) => const HomeScreen()), (route) => false)`.

## 3. Native Address Book Data Integrity & Normalization (P2)

### 3.1 Monolithic Full-Name Saving to First Name Field
- **Files:**
  - `contactqr_flutter/lib/data/repositories/contact_repository.dart` (line 139)
- **Problem:**
  In `insertContact()`, contact names are saved as `name: fc.Name(first: contact.name)`.
- **Impact:**
  The full name (e.g. `"Maria Santos"`) is placed entirely into the `First Name` field on Android/iOS. When the receiver sorts their address book by **"Last Name"**, "Maria Santos" is sorted under **"M"** instead of **"S"**.
- **Recommended Fix:**
  Split multi-word names into `first` and `last` fields:
  ```dart
  final parts = contact.name.trim().split(RegExp(r'\s+'));
  final firstName = parts.isNotEmpty ? parts.first : contact.name;
  final lastName = parts.length > 1 ? parts.sublist(1).join(' ') : '';
  final nativeName = fc.Name(first: firstName, last: lastName);
  ```

---

### 3.2 False-Positive Duplicate Collisions on 8-Digit Phone Matching
- **Files:**
  - `contactqr_flutter/lib/core/utils/phone_normalizer.dart` (lines 17–21)
- **Problem:**
  `extractCoreDigits(minDigits: 8)` compares only the last 8 digits of phone numbers.
- **Impact:**
  Numbers with different network prefixes but identical trailing digits (e.g. `0917 8123 4567` [Globe] vs `0918 8123 4567` [Smart]) are incorrectly flagged as duplicate contacts.
- **Recommended Fix:**
  Compare the last **10 digits** for standard mobile phone numbers to account for carrier prefixes.

---

### 3.3 Multi-Phone Number Truncation on Import
- **Files:**
  - `contactqr_flutter/lib/data/repositories/contact_repository.dart` (line 100)
- **Problem:**
  `getDeviceContacts()` only reads `c.phones.first.number`. If a contact has multiple numbers (Mobile, Work, Home), only the first is captured.
- **Recommended Fix:**
  Support primary/secondary phone labels and prioritize mobile numbers.

## 4. UI/UX Heuristics & Design System Polish (P2)

  Visual mismatch and design inconsistency across screens.

  Replace legacy color tokens with new design tokens.

### 4.3 Small Touch Target for "Skip All Duplicates" (Fitts's Law)
- **Files:**
  - `contactqr_flutter/lib/features/import/presentation/received_screen.dart` (line 95)
- **Problem:**
  The `Skip All` button has minimal padding with no minimum bounding box.
- **Impact:**
  Violates mobile 48x48dp touch target guidelines, making it difficult to tap on smaller smartphones.
- **Recommended Fix:**
  Provide a dedicated touch target container with at least 44–48dp tap area.

### 4.7 Responsive Layout Overflow on Landscape & Accessibility Font Scale (Miller's Law)
- **Files:**
  - `contactqr_flutter/lib/features/qr/presentation/widgets/enter_pin_modal.dart` (line 78)
  - `contactqr_flutter/lib/features/qr/presentation/widgets/set_pin_modal.dart` (line 83)
- **Problem:**
  PIN bottom sheets use fixed `Column` widgets without `SingleChildScrollView`.
- **Impact:**
  In landscape orientation or with increased OS text scaling, a yellow-black `RenderFlex overflowed by X pixels` error is triggered.
- **Recommended Fix:**
  Wrap modal content in `SingleChildScrollView`.

## 5. Optical QR, P2P Network & Scalability (P3)

### 5.1 QR Error Correction Level L vs Screen Glare & Smudges
- **Files:**
  - `contactqr_flutter/lib/features/qr/presentation/qr_screen.dart` (line 498)
- **Problem:**
  QR code is rendered with `QrErrorCorrectLevel.L` (7% fault recovery).
- **Impact:**
  Fingerprint smudges, lighting glare on phone glass, or low-light scanning frequently fail.
- **Recommended Fix:**
  Upgrade to `QrErrorCorrectLevel.M` (15% recovery) for higher scanning tolerance.

---

### 5.2 Missing Same-Network Advisory in Tier 2 Bulk Transfers
- **Files:**
  - `contactqr_flutter/lib/features/qr/presentation/qr_screen.dart` (lines 79–120)
- **Problem:**
  When transferring >30 contacts over local HTTP (Tier 2), if the sender is on cellular data and receiver on Wi-Fi, the connection will time out.
- **Recommended Fix:**
  Display a helper badge during Tier 2 transfers: *"Ensure both devices are on the same Wi-Fi or Personal Hotspot."*

---

### 5.3 Large Contact Batch Link Length in Social Messenger Apps (>50 Contacts)
- **Files:**
  - `contactqr_flutter/lib/features/qr/presentation/qr_screen.dart` (line 162)
- **Problem:**
  Sharing 50+ contacts via a URL link results in a hash fragment exceeding ~1.5–2KB.
- **Impact:**
  Some SMS gateways and messaging apps truncate links longer than ~2,000 characters.
- **Recommended Fix:**
  Show a helpful advisory recommending direct camera scan or Hotspot transfer for large contact batches.
